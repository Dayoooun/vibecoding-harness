# 강사용 — v0 Design System 등록 경로

**이 경로는 보너스다. 실패해도 수강생은 아무 영향을 받지 않는다.**

수강생 경로는 `common/10-long-prompt.md` 를 복사해 붙여넣는 것이고, 그 파일은 v0 계정 등급·Design System 기능과 무관하다. 이 사실은 문장이 아니라 참조 0건으로 증명된다 — `scripts/check-harness.mjs` 가 `common/` 과 `checklists/` 전체에서 Design System·`v0.json`·`SKILL.md` 참조를 검사하고, 하나라도 있으면 실패한다.

무료 플랜에서 Design System 임포트가 되는지는 **공식 문서에 명시가 없다.** 그래서 이 경로에 수강생을 태우지 않는다.

## 왜 하는가

성공하면 강사가 새 채팅마다 지침을 붙여넣지 않아도 된다. 툴바에서 스킬을 붙이면 v0 가 이 레포의 지침을 참조한다. 강의 시연에서 매번 프롬프트를 복사하는 동작이 사라진다.

## 선행 확인

1. Vercel GitHub App 이 `Dayoooun/vibecoding-harness` 에 접근 권한을 갖는지 확인한다. [GitHub App 설정](https://github.com/settings/installations)
2. v0 유료 플랜 계정으로 로그인한다.

## 절차 A — Git Import (레포가 무거운지 먼저 잰다)

레포가 무거우면 이후가 전부 무의미하므로 이것을 가장 먼저 한다.

1. v0 새 채팅의 첨부 메뉴에서 **Git Import** 를 연다.
2. `https://github.com/Dayoooun/vibecoding-harness` 를 붙여넣고 Import 한다.
3. Sandbox 클론과 의존성 설치가 끝날 때까지 **시계로 잰다.**

판정:

| 결과 | 처리 |
|---|---|
| 성공 | 소요시간을 기록한다. **이 값이 기준선이다** — 사전에 정한 임계값은 없다 |
| 실패 또는 타임아웃 중단 | **G1 게이트.** 레포 구조를 A2(파일 분할)에서 A1(단일 파일)로 되돌릴지 결정해야 한다 |

## 절차 B — Design System 임포트와 하위 파일 따라읽기 확인

이것이 이 레포 구조(파일 분할)의 유일한 미검증 가정이다. **`SKILL.md` 는 30줄짜리 라우팅 문서이고 실제 지침은 `common/` 아래에 있다. v0 가 그 링크를 따라 읽지 않으면 분할 구조가 무너진다.**

1. `v0.app/design-systems` 에서 Import 를 연다.
2. 소스로 `https://github.com/Dayoooun/vibecoding-harness` 를 넣는다.
3. v0 가 스타터를 빌드하고 검토를 요청하면, **저장 전에** 채팅에서 다음을 묻는다.

   > `common/00-core.md` 에 적힌 역할 슬롯 목록을 그대로 나열해줘.

4. 응답을 보고 아래 3분기 중 하나로 판정한다.

| 분기 | 무엇을 봤나 | 처리 |
|---|---|---|
| ⓐ 따라읽음 | 하위 파일의 내용을 정확히 인용한다 | **분할 구조 확정.** 그대로 진행한다 |
| ⓑ 안 읽음 | `SKILL.md` 내용만 알고 하위 파일을 모른다 | **G1b 게이트.** `SKILL.md` 에 공통층을 인라인하는 하이브리드로 전환한다. Phase 2 착수 전이면 손실은 골격뿐이다 |
| ⓒ 기능 자체 불가 | 계정 등급·지역·롤아웃 문제로 임포트 화면에 진입조차 못 한다 | **inconclusive.** 가정이 반증된 것이 아니므로 분할 구조를 유지한다. 이 경로는 보너스이므로 여기서 멈춰도 수강생 경로는 완전하다 |

ⓒ와 ⓑ를 구분하는 것이 중요하다. ⓑ는 설계를 바꿔야 하는 반증이고, ⓒ는 아무것도 알려주지 않는 미측정이다. 둘을 섞으면 멀쩡한 구조를 버린다.
